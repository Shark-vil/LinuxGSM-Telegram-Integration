# LinuxGSM Telegram Bot

Python-бот для управления уже установленными LinuxGSM-серверами по SSH или напрямую на Linux-хосте без SSH. Исходный каталог `LinuxGSM/` не изменён и в Docker-образ не включается.

## Запуск готового Docker-образа

Команды ниже предназначены для Bash на Linux. Клонировать репозиторий и устанавливать Python не нужно.

Создайте отдельный каталог для бота и файл `.env` внутри него:

```dotenv
BOT_TOKEN=123456789:ТОКЕН_ОТ_BOTFATHER
BOT_ADMIN=123456789
```

Укажите свой токен и Telegram ID администратора (либо `@username`). Подготовьте каталог данных; контейнер работает с UID/GID `10001:10001`:

```bash
mkdir -p data
sudo chown 10001:10001 data
sudo chmod 700 data
chmod 600 .env
```

Из этого каталога запустите бота:

```bash
docker run -d \
  --name linuxgsm-telegram-bot \
  --restart unless-stopped \
  --pull always \
  --env-file .env \
  --mount type=bind,src="$(pwd)/data",dst=/app/data \
  --read-only \
  --tmpfs /tmp:size=32m,mode=1777 \
  --cap-drop ALL \
  --security-opt no-new-privileges:true \
  ghcr.io/shark-vil/linuxgsm-telegram-integration:latest
```

Docker автоматически скачает образ. Откройте личный чат с ботом и отправьте `/start`; SSH-серверы можно добавлять через кнопки. Входящие порты и `-p` не нужны.

Файл `.env` остаётся на хосте и передаёт переменные окружения. Каталог `./data` хранит SQLite и `secret.key` вне контейнера, поэтому пользователи, серверы и SSH-реквизиты сохраняются при его пересоздании. Для резервной копии остановите контейнер и скопируйте **весь** `data`, включая ключ шифрования.

Логи: `docker logs -f linuxgsm-telegram-bot`. Остановка: `docker stop linuxgsm-telegram-bot`. Для обновления остановите и удалите контейнер (`docker rm linuxgsm-telegram-bot` после остановки), затем повторите команду запуска из того же каталога. Файлы в `./data` останутся на хосте.

### Готовый JSON и SSH-ключи с хоста

Если серверы заданы заранее, создайте рядом с `.env` каталог `config`, поместите JSON в `config/servers.json`, а приватные ключи при необходимости в `config/keys/`. Формат JSON описан ниже в разделе «Серверы в локальной сети из JSON» и в `servers.lan.example.json`. В JSON используйте `transport: "ssh"`, а относительный путь к ключу указывайте как `keys/minecraft_ed25519`. Пароль SSH или ключа задавайте в `.env` через переменную, указанную в `password_env` или `passphrase_env`.

Дайте группе контейнера доступ к конфигурации и ключам (команды для варианта с ключами):

```bash
sudo chgrp -R 10001 config
chmod 750 config config/keys
chmod 640 config/servers.json config/keys/*
```

Вместо предыдущей команды используйте следующую, с дополнительным подключением конфигурации **только для чтения**:

```bash
docker run -d \
  --name linuxgsm-telegram-bot \
  --restart unless-stopped \
  --pull always \
  --env-file .env -e SERVERS_FILE=/app/config/servers.json -e CONFIG_ONLY=true \
  --mount type=bind,src="$(pwd)/data",dst=/app/data \
  --mount type=bind,src="$(pwd)/config",dst=/app/config,readonly \
  --read-only \
  --tmpfs /tmp:size=32m,mode=1777 \
  --cap-drop ALL \
  --security-opt no-new-privileges:true \
  ghcr.io/shark-vil/linuxgsm-telegram-integration:latest
```

`CONFIG_ONLY=true` оставляет только серверы из JSON и отключает их добавление через чат. Для смешанного режима укажите `CONFIG_ONLY=false`. После изменения JSON, ключей или `.env` пересоздайте контейнер той же командой. Режим без SSH (`local`) требует запуска Python непосредственно на игровом Linux-хосте, как описано ниже.

## Запуск

1. Создайте бота через @BotFather и получите токен.
2. Скопируйте `.env.example` в `.env`. Укажите `BOT_TOKEN` и `BOT_ADMIN`: числовой Telegram ID либо `@username`.
3. Выполните `docker compose up -d --build`.
4. Откройте личный чат с ботом и отправьте `/start`.

Просмотр логов: `docker compose logs -f bot`. Остановка: `docker compose down`.
Нужен исходящий доступ контейнера к Telegram HTTPS и SSH-серверам. Входящие порты не нужны. Запускайте только один экземпляр бота на токен.

При первом обращении подходящего username администратор привязывается к Telegram ID в SQLite. Изменение username после этого не меняет владельца. Числовой ID предпочтительнее, поскольку username может сменить владельца до первого обращения. Изменение BOT_ADMIN после привязки не переносит права.

## Один сервер без SSH и без Docker

На машине с LinuxGSM запустите бота от того же Linux-пользователя, который управляет игрой. Не используйте root. SSH-сервис, SSH-ключи и открытые входящие порты не нужны. Скрипт запускается как локальный процесс с правами пользователя бота.

1. Скопируйте `servers.local.example.json` в `servers.json`, укажите настоящий абсолютный путь к игровому скрипту.
2. В `.env` вместе с токеном и администратором укажите:

```dotenv
SERVERS_FILE=./servers.json
CONFIG_ONLY=true
```

3. В каталоге проекта, уже под пользователем LinuxGSM, выполните:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
chmod 600 .env servers.json
set -a
. ./.env
set +a
.venv/bin/python bot.py
```

Это команды для Bash на Linux. Прямой запуск Python сам не читает `.env`: команды `set -a` и `. ./.env` экспортируют переменные. Файл должен быть вашим доверенным конфигом с синтаксисом shell; значения с пробелами или спецсимволами заключайте в одинарные кавычки. Docker Compose по-прежнему читает `.env` сам.

Перед началом работы каждый сервер из JSON проходит проверку файла и `details`. При ошибке бот не запускается; сообщение содержит ID сервера и причину, без вывода с возможными секретами. Это позволяет исправить конфигурацию до выдачи управления. Проверка повторяется при каждом запуске.

Для нескольких локальных скриптов добавьте объекты в массив JSON. Все они должны работать от одного пользователя бота. Если игры принадлежат разным Linux-пользователям, запускайте отдельные экземпляры с разными Telegram-токенами и каталогами `DATA_DIR` либо используйте SSH под соответствующими пользователями.

`local` означает машину, на которой работает процесс Python. В контейнере это был бы контейнер, поэтому бот отклоняет локальное выполнение внутри Docker. Простого монтирования игрового каталога недостаточно для управления процессами и tmux на хосте. Используйте запуск Python на хосте.

## Серверы в локальной сети из JSON

Используйте `servers.lan.example.json` как шаблон: укажите IP в LAN, пользователя, путь и проверенный SSH-отпечаток. Для пароля задайте `password_env` — имя переменной окружения с паролем, например `LAN_SSH_PASSWORD`. Для ключа укажите `auth: "key"`, `key_file` и при необходимости `passphrase_env`. Относительный `key_file` считается от каталога JSON. Сами SSH-секреты в JSON записывать не нужно.

Открывать SSH в интернет или пробрасывать порт на роутере не требуется: достаточно доступности SSH из сети, где работает бот. Если на другой машине SSH полностью отключён, сетевой доступ к её файлам сам по себе не позволяет управлять её процессами. Для этого запускайте локальный экземпляр бота на той машине.

Укажите путь через `SERVERS_FILE`. В одном JSON можно смешивать `local` и `ssh` при запуске бота на хосте. Поля `id` должны быть уникальными положительными целыми числами. Сохраняйте ID одного сервера при изменениях; не переиспользуйте его для другой машины, поскольку старые Telegram-кнопки ссылаются на него. Файл перечитывается при перезапуске.

При `CONFIG_ONLY=true` список содержит только серверы из JSON, добавление серверов в чате отключено, старые кнопки серверов из SQLite не выполняют команды. Уже сохранённые в SQLite данные не удаляются. При `CONFIG_ONLY=false` серверы из файла дополняют серверы из SQLite, а обычное добавление через чат остаётся доступным. Серверы из JSON не копируются в SQLite и не дублируются при перезапуске; конфигурация и файлы ключей остаются источником данных. Выдача/отзыв доступа к боту работает в обоих режимах.

Для предварительно настроенных SSH-серверов можно сохранить запуск через Compose: примонтируйте JSON и ключи в контейнер только для чтения и задайте `SERVERS_FILE` как путь **внутри контейнера**. Например, через дополнительный `compose.lan.yml`:

```yaml
services:
  bot:
    environment:
      SERVERS_FILE: /app/config/servers.json
    volumes:
      - ./servers.json:/app/config/servers.json:ro
      - ./keys:/app/config/keys:ro
```

Запуск: `docker compose -f docker-compose.yml -f compose.lan.yml up -d --build`. Пользователь контейнера UID 10001 должен иметь право чтения смонтированных файлов. В таком JSON используйте только `ssh`. Пароли/пароли ключей из `.env` передаются существующим `env_file`.

Во всех режимах Telegram требует **исходящий HTTPS-доступ в интернет**. Публичный IP, входящий доступ к боту и webhook не нужны: используется polling. Полностью офлайн Telegram-бот работать не сможет.

## Добавление сервера

Нажмите «Добавить сервер» и укажите название, IP, SSH-порт и пользователя — владельца LinuxGSM. Root не принимается. Бот получает публичный SSH-ключ без передачи учётных данных и показывает SHA256-отпечаток. Сверьте его через доверенный доступ к серверу, затем подтвердите.

Выберите пароль или SSH-ключ. Ключ отправляется документом до 64 КБ; поддерживаются RSA, Ed25519 и ECDSA, включая ключи с паролем. Для ключа без пароля отправьте `-`. Бот пытается удалить сообщения с паролем и ключом.

Поиск скриптов выполняется в `$HOME` SSH-пользователя на глубине до 5 каталогов; показываются первые 30 результатов. Можно указать абсолютный путь вручную, например `/home/steam/cs2server`. Файл должен быть исполняемым и содержать маркер LinuxGSM. Один сервер в списке бота соответствует одному управляющему скрипту: несколько игровых серверов на одном хосте добавляются отдельно.

Перед сохранением бот выполняет `details` и показывает вывод. При ненулевом коде сервер не сохраняется. Проверка не запускает и не останавливает игру, но LinuxGSM может создать свои логи или загрузить недостающие модули. На сервере должны быть установлены LinuxGSM и его зависимости. Используется обычное SSH-окружение без интерактивного login shell и без sudo.

## Управление и доступ

Кнопки: информация, запуск, остановка, перезапуск, проверка обновлений, обновление, резервная копия, отправка команды игровой консоли. Изменяющие состояние операции требуют подтверждения. `send` работает только для игр, в которых LinuxGSM поддерживает consoleinteract. Команда отправляется в игровую консоль; интерактивная SSH-консоль не предоставляется.

Вывод возвращается после завершения команды; длинный вывод прикладывается TXT-файлом, ограничение 512 КБ. На один добавленный сервер допускается одна операция одновременно; разные серверы могут работать параллельно. Командам отводится 15 минут. При локальном тайм-ауте группа запущенной команды принудительно завершается; уже отделившиеся игровые процессы могут продолжать работу. После SSH-тайм-аута состояние удалённого процесса не гарантируется: сначала проверьте информацию, затем решайте о повторе. `/cancel` отменяет ввод, но не останавливает уже отправленную SSH-команду.

Администратор добавляет и удаляет пользователей по числовому Telegram ID через кнопку «Пользователи». Человек без доступа может написать боту `/start`, чтобы узнать свой ID. Добавленные пользователи получают управление **всеми** добавленными серверами, включая остановку и обновление. Управление пользователями и добавление серверов остаются только у администратора. Групповые чаты игнорируются.

## Хранение и ограничения

SQLite и ключ шифрования находятся в Docker volume `bot-data`. SSH-реквизиты шифруются Fernet. Резервируйте весь volume целиком: без `secret.key` расшифровка невозможна. Не удаляйте volume командой `docker compose down -v`, если данные нужны.

При запуске без Docker эти данные лежат в `DATA_DIR` (по умолчанию `data/`). JSON, `.env` и приватные ключи храните отдельно с ограниченными правами; не добавляйте рабочие файлы с секретами в репозиторий.

Доступ к volume даёт доступ и к ключу расшифровки; шифрование не защищает от владельца Docker-хоста. Telegram-боты не используют сквозное шифрование: пароль, приватный ключ и вывод LinuxGSM проходят через Telegram. Используйте отдельный SSH-ключ и пользователя с необходимыми правами. Вывод `details` может содержать чувствительные сведения — всем допущенным пользователям предоставляйте соответствующий уровень доверия. Ключ SSH-хоста проверяется при каждом подключении; при его изменении требуется проверка и новое добавление сервера.

Незавершённые диалоги и подтверждения хранятся в памяти и сбрасываются после перезапуска. Уже сохранённые пользователи, серверы и администратор сохраняются. Установка игр, удаление/редактирование серверов, разграничение доступа по отдельным серверам и непрерывный просмотр логов не реализованы.

## Локальная проверка

Python 3.12+: `python -m pip install -r requirements.txt`, затем `python -m unittest -v`.
Локальный запуск: задайте переменные `BOT_TOKEN`, `BOT_ADMIN` и выполните `python bot.py`. Данные по умолчанию в `data/`, путь меняется через `DATA_DIR`.

Тесты проверяют привязку администратора, выдачу/отзыв доступа, шифрование, экранирование команд, чтение ключа, отказ при изменении SSH-ключа хоста, запрет сохранения при провале проверки и блокировку параллельных команд. Дополнительные тесты проверяют загрузку JSON, локальное выполнение, маршрутизацию без SSH, предварительную проверку и режим CONFIG_ONLY. Для реальной проверки нужны токен Telegram и Linux-хост с LinuxGSM; для SSH-режима также SSH-доступ.

Документация библиотек: [python-telegram-bot](https://docs.python-telegram-bot.org/en/stable/), [Paramiko](https://docs.paramiko.org/en/stable/).
